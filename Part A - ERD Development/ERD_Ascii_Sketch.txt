LEGEND:
================================================================================

PK = Primary Key (uniquely identifies each record in the entity)
FK = Foreign Key (links to primary key of another entity)

Crow's Foot Symbols:
  —— = One
  —o = Zero or One
  —{ = Many
  —o{ = Zero or Many (optional, many)

Relationship Lines:
  One-to-Many (1:M):      Entity1 ——o{ Entity2
  One-to-One (1:1):       Entity1 —— Entity2
  Zero-to-Many (0:M):     Entity1 —o{ Entity2
  Many-to-Many (M:N):     Entity1 —o{ Entity2 —o{ Entity1

================================================================================
RELATIONSHIPS SUMMARY:
================================================================================

1. DEPARTMENT 1:M DOCTOR (employs)
   └─ One department employs many doctors
   └─ Each doctor belongs to exactly one department
   └─ Foreign Key: Doctor.DepartmentID → Department.DepartmentID

2. DOCTOR 1:M APPOINTMENT (attends)
   └─ One doctor attends many appointments
   └─ Each appointment has exactly one doctor
   └─ Foreign Key: Appointment.DoctorID → Doctor.DoctorID

3. PATIENT 1:M APPOINTMENT (books)
   └─ One patient books many appointments
   └─ Each appointment belongs to exactly one patient
   └─ Foreign Key: Appointment.PatientID → Patient.PatientID

4. APPOINTMENT 1:1 CONSULTATION (results in)
   └─ Every appointment generates exactly one consultation record
   └─ Each consultation is linked to exactly one appointment
   └─ Foreign Key: Consultation.AppointmentID → Appointment.AppointmentID (UNIQUE)

5. DOCTOR M:N PATIENT (resolves via APPOINTMENT)
   └─ A doctor can consult with many patients
   └─ A patient can consult with many doctors
   └─ Junction table: APPOINTMENT

SYSTEM REQUIREMENTS SUPPORT:
================================================================================

✓ Patients register and maintain profiles
  → Stored in PATIENT table with all personal details

✓ Patients book appointments with doctors
  → APPOINTMENT links PATIENT to DOCTOR via foreign keys

✓ Patients cancel or reschedule appointments
  → AppointmentStatus field handles: Booked, Cancelled, Rescheduled, Completed

✓ Doctors view daily appointment schedules
  → Query APPOINTMENT joined with DOCTOR filtered by date and DoctorID

✓ Doctors record consultation notes
  → CONSULTATION table stores notes, diagnosis, treatment, follow-up date

✓ Receptionists create and manage appointments
  → Receptionists insert/update/delete records in APPOINTMENT table

✓ Each doctor belongs to a department
  → DOCTOR.DepartmentID foreign key enforces this relationship

✓ Patient may book multiple appointments
  → 1:M relationship between PATIENT and APPOINTMENT

✓ Doctor may attend multiple patients
  → 1:M relationship between DOCTOR and APPOINTMENT
  → Many-to-many resolved through APPOINTMENT junction

✓ Every appointment results in consultation record
  → 1:1 relationship enforced: APPOINTMENT generates CONSULTATION

✓ Reports on patient visits, doctor workloads, departmental performance
  → Can query across PATIENT, APPOINTMENT, DOCTOR, DEPARTMENT, CONSULTATION
